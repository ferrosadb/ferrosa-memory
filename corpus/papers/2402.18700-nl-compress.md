# Learning to Compress Prompt in Natural Language Formats (Nano-Capsulator)

**Authors:** Yu-Neng Chuang, Tianwei Xing, Chia-Yuan Chang, Zirui Liu, Xun Chen, Xia Hu
**arXiv:** [2402.18700](https://arxiv.org/abs/2402.18700)
**Published:** February 2024 (updated April 2024)

---

## Summary

Existing prompt compression methods produce soft (embedding-space) prompts that work only with the specific LLM used for compression. Nano-Capsulator compresses prompts into natural language "Capsule Prompts" — short, dense NL summaries that preserve the original prompt's utility and transfer across different LLMs, including API-based black-box models. Two challenges are addressed: NL prompts are not differentiable (solved with a reward function), and NL prompts need flexible length control (solved with a length-constraint reward term).

---

## Key Findings

- **81.4% length reduction** while preserving cross-LLM transferability.
- **4.5× inference latency reduction** from shorter context.
- **80.1% budget overhead reduction** (fewer tokens = lower API cost).
- **Full transferability across LLMs** — the capsule works on GPT-4, Llama, Claude, and others without recompression. This is the defining advantage over LLMLingua.
- **Reward-based training:** Since NL text is non-differentiable, the compressor is trained via RL with a semantic preservation reward and a length constraint reward.
- **Dual challenge addressed:** (1) Maintaining semantic fidelity in NL space; (2) controlling compressed length without hard token limits.

---

## Key Limitations

- Still some semantic loss at high compression ratios.
- Training the Nano-Capsulator requires a reward model pipeline.
- Compression quality depends on the quality of the reward model's semantic similarity judgment.

---

## Ferrosa Memory MCP Relevance

NL-Compress (Capsule Prompts) is the preferred compression format for `fold_summary` columns because of its cross-model transferability:

- **Multi-model environment requirement:** The RLM pattern uses multiple LLMs (root GPT-5, sub-call GPT-5-mini, local Qwen3-8B). A fold summary stored in NL capsule format works for all of them without recompression — critical for the `retrieve_fold_context` tool which must serve any requesting model.
- **`fold_summary` as NL capsule:** The `complete_fold` tool should write the fold summary in NL capsule format, produced either by running Nano-Capsulator on the raw trajectory or by prompting the LLM to produce a dense summary. The LLM-prompted approach is simpler in v1; Nano-Capsulator is the v2 upgrade for higher compression ratios.
- **81.4% reduction maps to storage tiers:** A 10MB raw trajectory compressed to ~1.9MB via NL capsule fits comfortably in NVMe hot storage even at moderate scale, delaying the need to tier to S3.
- **Dual use in `memo_cache`:** When storing a sub-call result in `memo_cache`, the `result` column should store the NL capsule of the sub-call output, not the raw output. This gives a compact representation that any model can consume on cache hit.
