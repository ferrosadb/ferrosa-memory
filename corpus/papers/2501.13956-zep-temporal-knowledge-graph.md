# Zep: A Temporal Knowledge Graph Architecture for Agent Memory

**Authors:** Preston Rasmussen, Pavlo Paliychuk, Travis Beauvais, Jack Ryan, Daniel Chalef
**arXiv:** [2501.13956](https://arxiv.org/abs/2501.13956)
**Published:** January 2025

---

## Summary

Standard RAG frameworks treat memory as static document retrieval. Zep addresses this with Graphiti — a temporally-aware knowledge graph engine that dynamically synthesizes both unstructured conversational data and structured business data while maintaining historical relationships. Facts are timestamped, supersession relationships are tracked, and the graph evolves as conversations continue. On DMR benchmark: 94.8% vs MemGPT's 93.4%. On LongMemEval: up to 18.5% accuracy improvement over baselines with 90% lower response latency.

---

## Key Findings

- **Temporal relationships are first-class.** Facts have valid-from/valid-until timestamps. When a fact changes ("Alice is the VP" → "Alice is the CEO"), the old fact is not deleted but marked superseded, preserving the full history.
- **18.5% accuracy improvement** on LongMemEval tasks specifically requiring temporal reasoning (e.g., "what was Alice's role before her promotion?"). Static RAG cannot answer these.
- **90% latency reduction** relative to baseline implementations that reload full conversation history.
- **Hybrid synthesis:** Both unstructured conversations and structured business data (CRM records, calendar events) are ingested and unified in the same graph.
- **Cross-session information synthesis** is where Zep's advantage is most pronounced — the temporal graph enables reasoning that spans multiple conversations over days or weeks.

---

## Key Limitations

- Graph maintenance (entity resolution, edge creation, supersession detection) adds write-path overhead.
- Entity resolution quality depends on the underlying LLM — poor resolution creates duplicate nodes.

---

## Ferrosa Memory MCP Relevance

Zep's design is the primary inspiration for the `temporal_events` table and the temporal chaining pattern in the spec.

- **`temporal_events` schema** directly implements Graphiti's temporal fact model: `event_time`, `supersedes_id`, `valid_until`, and the most-recent-valid-fact query pattern.
- **The 18.5% accuracy gain** on temporal reasoning tasks justifies making temporal chaining first-class rather than an afterthought column on `entity_store`. These are real-world enterprise scenarios (role changes, policy updates, project status) that Ferrosa DBaaS customers will encounter.
- **90% latency reduction** validates the architectural choice to index on `(tenant_id, entity_id, event_time)` with `CLUSTERING ORDER BY event_time DESC` — the most-recent query hits the first SSTable block.
- **Graph-traversable supersession chain:** `SUPERSEDES` edge type in Ferrosa's Cypher layer enables time-travel queries: "what did we know about entity X as of date D?" — a standard audit requirement.
- **Entity resolution via phonetic index:** The entity resolution problem Zep identifies (duplicate nodes from variant names) is addressed by the Double Metaphone index on `entity_store.entity_name` — phonetic matching deduplicates variants before node creation.
