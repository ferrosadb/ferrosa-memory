# ACON: Optimizing Context Compression for Long-Horizon LLM Agents

**Authors:** Minki Kang, Wei-Ning Chen, Dongge Han, Huseyin A. Inan, Lukas Wutschitz, Yanzhi Chen, Robert Sim, Saravan Rajmohan
**arXiv:** [2510.00615](https://arxiv.org/abs/2510.00615) (Microsoft)
**Published:** October 2025

---

## Summary

Prior context compression work focuses on single-step tasks or narrow applications. ACON addresses the full agentic scenario: an agent accumulates long action-observation histories across many steps, and both the environment observations *and* the interaction history need compression. ACON uses compression guideline optimization — given pairs of trajectories where full context succeeds but compressed context fails, an LLM analyzes the failure causes and updates the compression guidelines in natural language. Guidelines improve over time. The optimized compressor can be distilled into a small model.

---

## Key Findings

- **26–54% memory reduction** (peak token count) on AppWorld, OfficeBench, and Multi-objective QA.
- **95%+ accuracy preservation** when the optimized LLM compressor is distilled into a smaller model.
- **46% performance improvement** for smaller LMs as long-horizon agents when equipped with ACON compression.
- **Failure-pair learning:** The key insight is using (full context succeeds, compressed fails) pairs as the training signal. This is more informative than random compression examples because it directly targets the failure modes.
- **Natural language guideline format:** Guidelines are stored as NL text, interpretable by humans and any LLM. No fine-tuning or embeddings required for the guideline itself.
- **Distillation efficiency:** The optimized guideline, once learned via the large LLM, can be baked into a small specialist compressor (similar to ACON-mini).

---

## Key Limitations

- Guideline optimization requires running many agent trajectories to collect failure pairs — data-hungry.
- Quality of the optimized guideline depends on the analyzing LLM's reasoning ability.

## Ferrosa Memory MCP Relevance

ACON provides the design for the feedback learning loop — the mechanism by which the MCP server's routing and compression strategies improve over time:

- **`feedback_outcomes` table as failure-pair store.** Rows with `succeeded = false` are the ACON failure pairs: the full context (stored in `trajectory_folds`) succeeded, but the compressed summary failed. Exporting these pairs weekly feeds an ACON-style guideline optimizer.
- **Compression guidelines stored in Ferrosa.** Updated NL compression guidelines are versioned rows in a `routing_guidelines` config table, queryable by `guideline_version`. The MCP server loads the current guideline version on startup.
- **Per-tenant guideline specialization.** Different tenants have different workload types (code analysis, document QA, research). Running ACON's failure-pair optimization per tenant produces specialized guidelines that outperform generic ones.
- **Distillation path to WASM UDF.** Once a compression guideline is sufficiently stable, ACON's distillation step produces a small model that can run as a Ferrosa WASM UDF (within memory/CPU limits) — eliminating the external sidecar dependency for compression.
- **46% improvement for small LMs** is directly relevant for local-model deployments (Qwen3-8B on RTX 3090). The ACON-compressed context unlocks performance that would otherwise require a larger model.
