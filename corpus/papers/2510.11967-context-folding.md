# Scaling Long-Horizon LLM Agents via Context-Folding

**Authors:** Weiwei Sun, Miao Lu, Zhan Ling, Kang Liu, Xuesong Yao, Yiming Yang, Jiecao Chen
**arXiv:** [2510.11967](https://arxiv.org/abs/2510.11967)
**Published:** October 2025

---

## Summary

LLM agents on long-horizon tasks accumulate context until they hit the context window limit, then either fail or fall back to lossy summarization that discards critical intermediate state. Context-Folding introduces a structured alternative: when a sub-task is complete, the agent *folds* the sub-trajectory — replacing the full intermediate history with a concise outcome summary — and then resumes the parent trajectory. This is trained end-to-end with reinforcement learning (FoldGRPO) using process rewards that encourage effective task decomposition and compact folding. The result is 10× smaller active context with equal or better performance.

---

## Key Findings

- **10× active context reduction** while matching or outperforming ReAct baselines on Deep Research and SWE tasks.
- **Outperforms summarization-based context management substantially** — lossy rolling summarization discards fine-grained information that folding preserves via structured outcome representation.
- **FoldGRPO training:** RL with process rewards targeting (a) correct fold decision timing and (b) compact, accurate fold summaries. The model learns *when* to fold, not just *how* to fold.
- **Fold hierarchy is naturally tree-structured:** Sub-tasks fold into parents; the result is a tree of fold summaries addressable from the root without loading any intermediate history.
- **Fold quality matters:** Poor fold summaries (too terse or inaccurate) degrade downstream performance. The RL reward signal targets both compactness and accuracy.

---

## Key Limitations

- FoldGRPO training requires task-specific process reward design.
- Fold timing decisions add decision overhead per trajectory step.

## Ferrosa Memory MCP Relevance

Context-Folding is the direct inspiration for the `trajectory_folds` table and the `start_fold`/`append_to_fold`/`complete_fold` tool trio.

- **`trajectory_folds` schema** implements the fold lifecycle: `status` transitions from `active` → `folded` → `archived`, with `raw_trajectory` and `fold_summary` as separate columns supporting the full/compressed access pattern.
- **`FOLDED_INTO` graph edges** make the fold tree navigable via Cypher without loading raw content — exactly the hierarchy addressability the paper demonstrates.
- **`retrieve_fold_context` via HNSW** enables the equivalent of FoldGRPO's fold-lookup step: given the current query, find the most semantically relevant fold summary from prior sub-trajectories.
- **The 10× context reduction** directly translates to token cost reduction per agent session — a concrete cost metric for the DBaaS pricing model.
- **Fold quality via NL compression:** The fold summary quality concern maps to using NL-Compress (model-agnostic capsule compression) for fold summaries rather than naive truncation.
