# Terrarium: Revisiting the Blackboard for Multi-Agent Safety, Privacy, and Security Studies

**Authors:** Mason Nakamura, Abhinav Kumar, Saaduddin Mahmud, Sahar Abdelnabi, Shlomo Zilberstein, Eugene Bagdasarian
**arXiv:** [2510.14312](https://arxiv.org/abs/2510.14312)
**Published:** October 2025

---

## Summary

Multi-agent systems powered by LLMs enable automation of complex collaborative tasks, but introduce new risks when agents share state through a common memory or communication layer. Terrarium revives the *blackboard architecture* from classical AI — a shared workspace that all agents can read from and write to — and uses it as a configurable testbed for studying safety, privacy, and security in LLM-based multi-agent systems. The framework implements four representative attack types across three collaborative scenarios, enabling rapid prototyping and evaluation of defenses.

---

## Key Findings

- **Shared memory is a primary attack surface.** The blackboard (shared memory) expands the attack surface beyond individual agents: compromising any single agent with write access to the blackboard can affect all downstream agents that read from it.
- **Four key attack vectors identified:**
  1. **Misalignment** — agents pursue different objectives than intended due to ambiguous instructions
  2. **Malicious agents** — a compromised agent deliberately injects false information into shared memory
  3. **Compromised communication** — an adversary intercepts and modifies agent-to-agent messages
  4. **Data poisoning** — malicious content in the environment propagates into shared memory via normal agent operation (related to MemoryGraft)
- **Blackboard design enables modular defense prototyping.** Because all shared state flows through one structure, defenses can be applied at the blackboard level (validation, sanitization, access control) rather than per-agent.
- **Framework flexibility demonstrated** across meeting scheduling, document collaboration, and web research scenarios.
- **Privacy risks are distinct from security risks:** Even without an active attacker, agents sharing a blackboard can inadvertently expose one user's private context to another user's agent session.

---

## Key Limitations

- The blackboard architecture is a testbed/framework, not a deployable system design.
- Attack scenarios are representative, not exhaustive.

## Ferrosa Memory MCP Relevance

Terrarium provides the multi-agent threat model that informs the spec's security architecture — specifically the tenant isolation and audit log designs. The Ferrosa `agent_memory` keyspace *is* a blackboard architecture, and Terrarium's attack taxonomy applies directly:

- **Misalignment defense → plan_state with explicit goal_text:** Each plan node stores the goal text that was active when it was written. If an agent writes a node with a subtly misaligned goal, the audit log captures it and the parent can detect the drift on the next `get_plan_context` call.
- **Malicious agent defense → write-time confidence gating + source linkage:** Every write to `entity_store` and `trajectory_folds` carries `source_fold_id` — the trajectory that produced it. A compromised sub-agent's writes are traceable to its specific session, enabling quarantine without affecting other agents' memory objects.
- **Compromised communication defense → MCP server as the single write path:** All memory writes go through the MCP server (not directly to CQL), which enforces schema validation, confidence gating, and auth on every write. There is no bypass path for agent-to-agent direct writes.
- **Data poisoning defense:** Identical to the MemoryGraft defense — confidence gating, anomaly detection, audit trail. Terrarium frames this as an inter-agent concern; MemoryGraft frames it as an environmental injection concern. Both are addressed by the same mechanisms.
- **Privacy in multi-agent scenarios → tenant_id isolation:** Terrarium's finding that agents can inadvertently expose cross-user private context maps to the tenant_id partition key requirement. Even if two sub-agents within the same session are running different user tasks, their memory objects are keyed to the session tenant — no cross-contamination.
- **Blackboard-level defense centralization:** Terrarium's insight that defending at the shared-memory level is more efficient than per-agent defense validates the spec's choice to put security logic in the MCP server (the access point to the blackboard) rather than in each tool client.
