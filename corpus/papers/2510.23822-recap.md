# ReCAP: Recursive Context-Aware Reasoning and Planning

**Authors:** Zhenyu Zhang, Tianyi Chen, Weiran Xu, Alex Pentland, Jiaxin Pei
**Venue:** NeurIPS 2025
**arXiv:** [2510.23822](https://arxiv.org/abs/2510.23822)
**Published:** October 2025

---

## Summary

Sequential prompting on long-horizon tasks suffers from context drift, goal loss, and failure cycles as the prompt grows. Hierarchical approaches can fix this but either weaken cross-level continuity or create prohibitive overhead. ReCAP introduces three mechanisms that together solve the problem: plan-ahead decomposition, structured re-injection of parent plans on recursive return, and memory-efficient execution that bounds active prompt size so costs scale linearly with task depth rather than quadratically.

---

## Key Findings

- **32% improvement** on synchronous Robotouille and **29% improvement** on asynchronous Robotouille (strict pass@1 protocol) — both large-margin gains over state-of-the-art hierarchical prompting methods.
- **Three mechanisms, all necessary:**
  1. **Plan-ahead decomposition** — generate the full subtask list first, execute the first item, then refine the remainder. Prevents myopic one-step planning.
  2. **Structured re-injection** — when returning from a recursive call, re-inject the parent plan context in a fixed, compact structure. Preserves cross-level continuity without expanding the window.
  3. **Memory-efficient execution** — active prompt is bounded to O(depth) rather than O(total steps). Linear cost scaling confirmed empirically.
- **Goal alignment** is the primary failure mode ReCAP addresses — agents forget their high-level objectives while executing low-level steps. Structured re-injection directly prevents this.
- **Asynchronous tasks** (where sub-tasks execute in parallel with interleaving) are where the gain is largest — the 29% improvement reflects situations where context management is hardest.

---

## Key Limitations

- Plan-ahead decomposition requires the model to have a good prior on the full task structure upfront; may fail on poorly-specified tasks.
- Re-injection adds tokens per recursive call; the linear-cost claim depends on compact plan representations.

## Ferrosa Memory MCP Relevance

ReCAP is the direct design source for the `plan_state` table and the `write_plan_node`/`get_plan_context`/`update_plan_node` tool triad.

- **`plan_state` schema** implements structured re-injection: `(session_id, depth, subtask_id)` as the partition/clustering key enables O(depth) range scans. `parent_subtask` and `goal_text` columns provide the compact parent context for re-injection.
- **Linear cost scaling guaranteed** by the wide-row data model: `WHERE session_id = ? AND depth <= N` is a single partition scan regardless of total session history.
- **`get_plan_context` return value** is the re-injection payload — a compact JSON tree the LLM prepends to its prompt on each recursive return, implementing ReCAP's mechanism 2 without manual prompt engineering.
- **`status` field transitions** (pending → active → complete/failed) implement ReCAP's plan refinement loop: marking a node failed triggers the parent to re-decompose remaining subtasks.
- **The 32%/29% gains are directly reproducible** with this storage design if the LLM is instructed to use `get_plan_context` on each sub-task entry and exit.
