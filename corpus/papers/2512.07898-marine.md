# MARINE: Multi-Agent Recursive In-Context Enhancement

**Authors:** Hongwei Zhang, Ji Lu, Yongsheng Du, Yanqin Gao, Lingjun Huang, Baoli Wang, Fang Tan, Peng Zou
**arXiv:** [2512.07898](https://arxiv.org/abs/2512.07898)
**Published:** December 2025

---

## Summary

LLM-based agents are typically constrained to single responses, leaving significant performance potential unrealized when a problem benefits from iterative refinement. MARINE reconceptualizes test-time reasoning as iterative refinement of a *persistent reference trajectory* — rather than sampling N independent responses and picking the best, the system maintains a shared trajectory that is progressively improved across iterations. Rigorous theoretical analysis establishes optimal batch scheduling. A 80B model with MARINE matches a 1000B standalone agent in quality.

---

## Key Findings

- **80B matches 1000B:** MARINE allows a model 12.5× smaller to match a much larger standalone model by converting pass@N capability into near-optimal pass@1 through iterative refinement.
- **46.0% pass@1 on BrowserComp-ZH** (Chinese browser research benchmark) with a 685B implementation — state-of-the-art.
- **Persistent reference trajectory is the key primitive.** Rather than independent samples, each iteration reads the current trajectory state, identifies weaknesses, and improves it. This is fundamentally different from majority voting or best-of-N selection.
- **Theoretical batch scheduling:** Minimal feasible batch sizes maximize expected performance gains under fixed invocation budgets. Logarithmically growing batches ensure continuous improvement without bounds.
- **Better alignment data:** Within a fixed compute budget, MARINE produces higher-quality samples for post-training than traditional sampling-and-ranking strategies — compounding benefit over time.

---

## Key Limitations

- Iterative refinement adds latency proportional to iteration count.
- Trajectory coherence can degrade if refinement iterations pull in conflicting directions.

## Ferrosa Memory MCP Relevance

- **The persistent reference trajectory is a first-class memory object.** In Ferrosa, this maps to a `trajectory_folds` row with `status = 'active'` that multiple `append_to_fold` calls update iteratively rather than a single completion. The SUBSCRIBE DELTA endpoint lets consumers stream each refinement as it lands.
- **Append semantics match Ferrosa's LSM-tree model.** Each refinement iteration appends a new version row rather than overwriting — LSM-trees are naturally optimized for high-throughput append workloads, making Ferrosa a good fit.
- **Minimum batch size → memtable flush tuning.** The theoretical result about minimal batch sizes translates to a practical write-path configuration: buffer refinement iterations in the memtable until a minimum batch size is reached before flushing to SSTable. This reduces write amplification and matches MARINE's recommendation.
- **Alignment data harvesting.** The `feedback_outcomes` table accumulates (session, trajectory, outcome) triples that can serve as MARINE-quality training data for the guideline refinement model — a flywheel where the system improves its own routing as it accumulates successful trajectories.
