# MemoryGraft: Persistent Compromise of LLM Agents via Poisoned Experience Retrieval

**Authors:** Saksham Sahai Srivastava, Haoyu He
**arXiv:** [2512.16962](https://arxiv.org/abs/2512.16962)
**Published:** December 2025

---

## Summary

LLM agents that learn from experience by storing past task outcomes in a RAG-backed memory store introduce a novel attack surface: the trust boundary between the agent's reasoning core and its own past. MemoryGraft exploits the agent's *semantic imitation heuristic* — the tendency to replicate patterns from retrieved successful tasks — by injecting malicious procedure templates disguised as legitimate successful experiences. Unlike transient prompt injections, MemoryGraft is persistent: the poisoned entries survive session boundaries and activate whenever semantically similar tasks trigger retrieval.

---

## Key Findings

- **Semantic imitation heuristic is the attack vector.** Agents don't just retrieve relevant memories — they replicate the *procedure* of successful retrieved memories. An attacker who can supply one benign-looking artifact that the agent reads during execution can implant a malicious procedure template in the memory store.
- **Small number of records → high retrieval domination.** A small number of poisoned records can account for a large fraction of retrieved experiences on benign workloads due to union retrieval over lexical *and* embedding similarity — both paths surface the same poisoned records.
- **Persistent behavioral drift.** Unlike prompt injection (transient, per-session), MemoryGraft persists across sessions. The compromised behavior is durable until the poisoned records are explicitly identified and removed.
- **Validated on MetaGPT DataInterpreter + GPT-4o.** Attack success demonstrated on a production-grade agent system — not a toy scenario.
- **Indirect injection:** The attacker does not need direct access to the memory store. Supplying a malicious document during normal agent execution is sufficient for the agent to ingest and store the poisoned template.

---

## Key Limitations

- Requires the attacker to be able to supply content the agent reads during normal operation (e.g., a document in a corpus, a web page the agent visits).
- Detection is difficult because poisoned records are syntactically indistinguishable from benign ones.

---

## Ferrosa Memory MCP Relevance

MemoryGraft is the most directly threatening attack paper for ferrosa-memory-mcp. Every design decision in the security section of the spec traces back to this paper:

- **Write-time confidence gating** (spec §7.2): Rejects `upsert_entity` and `store_memo_result` calls below a confidence threshold. Poisoned records typically arrive via indirect injection paths (agent reads a document, agent stores what it "learned") which produce lower-confidence results than direct human input.
- **Union retrieval deduplication** (spec §7.2): The paper explicitly identifies union retrieval over lexical + embedding similarity as the mechanism that amplifies a small number of poisoned records into majority retrieved results. The `retrieve_entities` deduplication step by entity identity before returning breaks this amplification.
- **Anomaly detection view** (spec §7.2): Materialized view tracking retrieval frequency per entity per session. The MemoryGraft attack pattern produces anomalously high retrieval frequency for a small set of injected records — a 3σ threshold surfaces this before the behavioral drift becomes severe.
- **Append-only audit log** (spec §7.2): Since poisoned records are persistent, detection depends on being able to audit *when* a record was written and *from what source*. The audit log provides the forensic trail needed to identify and quarantine poisoned entries.
- **`confidence` field on all write tools**: Confidence is not optional decoration — it is the primary defense signal. The `source_fold_id` linkage on `entity_store` enables tracing any written entity back to the trajectory that produced it, which is essential for post-detection cleanup.
