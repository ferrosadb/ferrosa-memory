# Recursive Language Models (RLMs)

**Authors:** Alex L. Zhang, Tim Kraska, Omar Khattab
**Institution:** MIT CSAIL
**arXiv:** [2512.24601](https://arxiv.org/abs/2512.24601)
**Published:** January 2026

---

## Summary

LLMs suffer from "context rot" — performance degrades steeply as prompts grow longer, even within their stated context windows. RLMs solve this by treating the entire input prompt as an external environment variable in a Python REPL rather than feeding it into the neural network directly. The LLM writes code to peek at, decompose, and recursively invoke itself over slices of that variable. This gives the model effectively unbounded input and output length with no architectural changes — only an inference-time scaffold.

---

## Key Findings

- **100× context extension:** RLMs successfully process inputs two orders of magnitude beyond the model's native context window (up to 10M+ tokens demonstrated).
- **Performance advantage:** RLMs substantially outperform base models and all standard long-context scaffolds (context compaction, CodeAct+BM25, retrieval agents) across four diverse tasks.
- **Three design choices matter:** (1) prompt as REPL variable (not in context), (2) output via variables (not autoregressive Finish), (3) sub-calls invoked programmatically in loops (not verbalized one-at-a-time). Any missing element collapses to a far weaker scaffold.
- **Cost parity:** Median RLM run is comparable in cost to a base model call; 3× cheaper than summarization agents on long corpus tasks. High variance at the tail.
- **Small model training:** RLM-Qwen3-8B, trained on only 1,000 filtered trajectories from a larger model, improves over baseline Qwen3-8B by 28.3% on average and approaches GPT-5 quality on three tasks.
- **Task complexity taxonomy:** O(1) complexity (NIAH) → frontier models cope well. O(n) complexity (OOLONG) → RLMs outperform base by ~30%. O(n²) complexity (OOLONG-Pairs) → base models near-zero, RLMs achieve 23–58% F1.

---

## Key Limitations Noted

- Chunking strategy is naive (uniform splits or keyword regex); no semantic pre-filtering.
- Sub-calls are synchronous/blocking — asynchronous execution could cut runtime significantly.
- Models without strong coding ability fail as RLMs.
- Depth capped at 1 (sub-calls are plain LMs, not recursive RLMs themselves).
- Thinking models may exhaust output token budgets on long trajectories.

## Ferrosa Memory MCP Relevance

This is the foundational paper for the entire system. Key implications:

- The REPL variable pattern means all intermediate state that currently lives as ephemeral Python variables is the target for persistent storage — this defines every table in the `agent_memory` keyspace.
- The naive chunking bottleneck is the primary motivation for the HNSW and phonetic indexes: replace regex keyword search with semantic and fuzzy retrieval.
- The tail cost variance problem (cheap median, expensive outliers) is the primary motivation for the memoization layer: cache sub-call results to eliminate redundant recursion.
- The O(n) / O(n²) task taxonomy maps directly to `task_complexity` classifications in the `feedback_outcomes` table, enabling routing decisions based on expected computational complexity.
- The 1,000-sample fine-tuning result validates the feedback loop design: small amounts of trajectory data drive large gains, so the `feedback_outcomes` store has high expected ROI.
