# Continuum Memory Architecture (CMA) for Long-Horizon LLM Agents

**Authors:** Joe Logan
**arXiv:** [2601.09913](https://arxiv.org/abs/2601.09913)
**Published:** January 2026

---

## Summary

RAG treats memory as a stateless lookup table: information persists indefinitely, retrieval is read-only, and there is no temporal continuity. This paper defines the Continuum Memory Architecture (CMA) — a class of systems that maintain and *update* internal state across interactions. CMA is framed as a necessary architectural primitive for long-horizon agents, not an optimization. Five behavioral primitives are specified and empirically validated against RAG's structural inability to handle them.

---

## Key Findings

- **RAG structural failures demonstrated** on four probe tasks: knowledge updates (RAG retrieves stale facts), temporal association (RAG cannot reason about when facts changed), associative recall (RAG cannot chain associations), contextual disambiguation (RAG cannot resolve ambiguity using conversation history).
- **Five CMA primitives required:**
  1. **Persistent storage** — memory survives session boundaries
  2. **Selective retention** — not everything should be kept; active forgetting
  3. **Associative routing** — retrieval is directed by content relationships, not just query similarity
  4. **Temporal chaining** — facts have timestamps and supersession relationships
  5. **Consolidation** — lower-level memories can be abstracted into higher-order representations
- **CMA behavioral advantages are consistent** across all four probe task categories where RAG fails.
- **Open challenges identified:** Latency (consolidation is expensive), drift (accumulated state may diverge from ground truth), interpretability (hard to audit what the system "knows").

---

## Key Limitations

- Theoretical/architectural paper; does not disclose implementation specifics.
- Does not provide head-to-head numbers against specific RAG implementations.

## Ferrosa Memory MCP Relevance

This paper provides the clearest theoretical justification for the entire `agent_memory` keyspace design. Each CMA primitive maps to a specific Ferrosa component:

| CMA Primitive | Ferrosa Implementation |
|---|---|
| Persistent storage | S3-backed SSTable storage; session data survives process restarts |
| Selective retention | Confidence gating on writes; `expires_at` TTL; Glacier tiering |
| Associative routing | HNSW ANN + phonetic index; tool routing layer |
| Temporal chaining | `temporal_events` table with `supersedes_id` and `valid_until` |
| Consolidation | `trajectory_folds` fold/summarize pattern; NL capsule compression |

The "drift and interpretability" challenge maps directly to the audit log requirement and the `system_observability.memory_summary` virtual table — the system needs to be externally auditable to detect and correct drift.
