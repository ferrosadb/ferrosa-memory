# SRLM: Self-Reflective Recursive Language Models

**Authors:** Keivan Alizadeh, Parshin Shojaee, Minsik Cho, Mehrdad Farajtabar
**arXiv:** [2603.15653](https://arxiv.org/abs/2603.15653)
**Published:** March 2026

---

## Summary

A direct follow-up to the RLM paper that challenges its core assumption. SRLM finds that recursion itself is not the primary performance driver — the quality of the context-interaction *program* selected before execution is what matters. SRLM augments RLM with uncertainty-aware self-reflection: three intrinsic signals (self-consistency across samples, reasoning trace length, verbalized confidence) are used to evaluate and rank candidate programs before committing to one. This program selection step delivers up to 22% improvement over vanilla RLM under the same time budget.

---

## Key Findings

- **Program selection > recursion:** A simple self-reflective program search can match or surpass RLM without requiring self-query or explicit recursion mechanisms.
- **Recursion can hurt:** For inputs within the model's native context window, adding RLM recursion *degrades* performance relative to the base model. RLMs are only clearly beneficial when inputs exceed the context window.
- **Three uncertainty signals:** Self-consistency (same query, multiple samples, check agreement), reasoning length (proxy for model confidence), verbalized confidence (model's stated certainty) are complementary — no single signal dominates.
- **22% improvement** over vanilla RLM under identical time budgets on diverse benchmarks.
- **Semantic task gap:** RLM is weakest on tasks with high semantic intensity where heuristic program search is insufficient. Self-reflection provides a semantic signal that better steers reasoning in these cases.

---

## Key Limitations

- Self-reflection adds latency — the multiple sample generation step has overhead.
- Uncertainty signal quality varies by model; some models are poorly calibrated in verbalized confidence.

## Ferrosa Memory MCP Relevance

- **Directly informs the tool routing layer.** The finding that program selection is the primary performance driver means the MCP server's routing logic is more important than the underlying storage operations. The `feedback_outcomes` table accumulates the signal needed to improve routing quality over time.
- **Uncertainty signals map to retrieval confidence thresholds.** Self-consistency and verbalized confidence translate into the `confidence` field on `entity_store` writes and the confidence gating on `store_memo_result`. Low-confidence writes are excluded from the hot retrieval path.
- **Validates the feedback loop design.** SRLM's iterative program selection is essentially online learning over retrieval strategies — the `feedback_outcomes` + nightly guideline refresh implements this offline.
- **Context window boundary as a routing signal.** The finding that RLMs hurt within the context window means the MCP server should include context size as a routing input: small requests bypass storage entirely, large ones invoke the full memory stack.
