System Integration

This shell sits above the same authenticated operator APIs as viz, using the Ferrosa console chrome for every surface instead of a separate admin theme.

  • CQL passthrough endpoint: /workbench/api/cql/query (read-only)
  • SPARQL passthrough endpoint: /workbench/api/sparql/query (wire contract forwarded)
  • Local Datalog inference endpoint: /workbench/api/datalog/query (ferrosa-memory engine)
  • Judge config endpoint: /workbench/api/judge/config
  • Explanation drilldown: /workbench/api/explanations/query
  • Rules endpoint: /workbench/api/rules
  • Approvals endpoint: /workbench/api/approvals

CQL Explorer

Run read-only storage inspection queries through the CQL passthrough contract. The workbench forwards the payload without SQL translation, so request and response contract errors are surfaced directly.

Run CQL

The CQL surface sends a passthrough payload to /workbench/api/cql/query with query and limit fields. Ferrosa contract errors are returned directly, so keyspace qualification and filtering rules must match the public CQL behavior.

Read-only passthrough Common app tables: agent_memory.entity_store, agent_memory.rules_by_id, agent_memory.rules_by_family, agent_memory.aliases_by_name, agent_memory.approvals_by_target, agent_memory.derived_cache_by_pred

Operator note: qualify app tables explicitly with agent_memory.. Ferrosa/Cassandra enforces real partition-key semantics here, so query rules_by_family or derived_cache_by_pred with their keyed access patterns, or add ALLOW FILTERING only if that contract is intentional.

The endpoint accepts predicate and optional session_id. This is the local Datalog inference contract in ferrosa-memory; selected rows are reused automatically in explanation payloads.

Selected rows automatically supply src_id and dst_id to the explanation endpoint. Manual drilldown remains available for ad hoc payloads.
