# memory-sync — Architecture Spec

## Overview

`memory-sync` is a CLI binary that replicates the memory contents of one Ferrosa environment
into another. Primary use case: pull memories from a remote server (e.g., a production node) into
a local development environment, or migrate between environments.

This document describes the current admin-path implementation, which still uses direct CQL storage bindings. Per ADR-005, the desired runtime architecture for `ferrosa-memory` is public-API-only; this sync tool should eventually move to Ferrosa public interfaces as well.

## Usage

```sh
# Pull from remote into local (most common)
memory-sync --source remote.toml --dest local.toml --tenant-id <UUID>

# Dry-run: report what would be synced without writing
memory-sync --source remote.toml --dest local.toml --tenant-id <UUID> --dry-run
```

Both `--source` and `--dest` accept paths to `ferrosa-memory.toml`-format config files.
At minimum, each file must contain a `[ferrosa]` section with `contact_points`.

## What Gets Synced

| Table              | Method                                   | Notes                                 |
|--------------------|------------------------------------------|---------------------------------------|
| `entity_store`     | `entity_list_all` → `entity_put`         | Full fidelity incl. embeddings        |
| `trajectory_folds` | `fold_list_all` → `fold_put`+`fold_complete` | Two-step write to match schema  |
| `temporal_events`  | `temporal_list_all` → `temporal_put`     | Preserves event_time / event_id       |
| `intentions`       | `intention_list` → `intention_put`       | Full fidelity                         |
| `feedback_outcomes`| `feedback_list_all` (filtered) → `feedback_put` | Filtered by --tenant-id        |
| `folded_into`      | raw CQL read → `edge_folded_into`        | Edge created_at reset to sync time    |
| `mentioned_in`     | raw CQL read → `edge_mentioned_in`       | Edge created_at reset to sync time    |
| `co_occurs_with`   | raw CQL read → `edge_co_occurs`          | strength preserved; timestamps reset  |
| `supersedes`       | raw CQL read → `edge_supersedes`         | Edge created_at reset to sync time    |

**Skipped tables**: `audit_log` (audit trail should not be replicated),
`entity_retrieval_counts` (baseline for anomaly detection, re-built on use),
`memo_cache` (cache, not memory), `plan_state` (session-specific scaffolding),
`routing_guidelines` (generated by batch job).

## Conflict Handling

CQL INSERT is upsert-by-primary-key — a re-sync of the same tenant is idempotent for all tables
whose primary keys are UUIDs or timeuuids. For `co_occurs_with`, re-inserting preserves the
synced strength value (last write wins).

Edge `created_at` timestamps are set to sync time (edge write methods call `Utc::now()`). This is
a known limitation — edge timestamps are used only for pruning, not for memory recall.

## Data Flow

```
Source Ferrosa environment                     Destination Ferrosa environment
  192.168.202.88:19042                           localhost:19042
        │                                               │
   current CqlStorage (src)                     current CqlStorage (dst)
        │                                               │
        └──── fold_list_all ──────────────────────────► fold_put / fold_complete
        └──── entity_list_all ────────────────────────► entity_put
        └──── temporal_list_all ──────────────────────► temporal_put
        └──── intention_list ─────────────────────────► intention_put
        └──── feedback_list_all (filtered) ───────────► feedback_put
        └──── raw CQL (edge tables) ──────────────────► edge_folded_into / edge_mentioned_in
                                                         edge_co_occurs / edge_supersedes
```

## Storage Trait Additions

Two new methods added to `ferrosa_memory_core::storage::Storage` to support full-table reads:

```rust
/// List all folds for a tenant (sync/export use only).
async fn fold_list_all(&self, ctx: &TenantContext) -> anyhow::Result<Vec<FoldEntry>>;

/// List all temporal events for a tenant (sync/export use only).
async fn temporal_list_all(&self, ctx: &TenantContext) -> anyhow::Result<Vec<TemporalEvent>>;
```

Both use `ALLOW FILTERING` on `tenant_id` — acceptable for an admin/maintenance binary,
not for production query paths.
