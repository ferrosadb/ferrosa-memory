The model · buckets over rungs

DIKW is the default, not the vocabulary

A person names their own buckets — financial knowledge, engineering information, trash. Underneath, each one sits on a DIKW rung, because several things already depend on the tiers being ordered: the sharing floor is written as a floor, and Data is the floor that "unclassified" falls to. A flat set of arbitrary labels has neither.

So the bucket is the person's word and the rung is the machinery's. The meter shows the rung, which means two buckets can share one meter — and the name is what tells them apart.

Data Arrived somehow. Nobody placed it. default
Trash Kept, never surfaced. Suppression, not a rung. yours
Information Curated, but someone else's. default
Engineering information Specs, drivers, vendor docs. yours
Knowledge Worked out here. Rules sit at this rung too. default
Financial knowledge Board packs, models, the numbers behind them. yours
Wisdom How we decide. Smallest and most valuable. default

Creating a bucket has blast radius of its own: one placed at the wrong rung quietly changes what is shareable. "Trash" is the case the rule language cannot state yet — everything except trash is an exclusion, which is what negation is for.

5 · A rule is a handle on its yield

Opening a rule shows what it classified, and offers three acts over exactly that set. Once a rule names a body of material, every bulk thing someone wants to do is a thing done to that set.

The three differ enormously in reversibility, so they must not look alike. Deleting the rule returns items to the pile and is undone by re-creating it. Deleting the data is not undone by anything.

Sharing by rule shares a live set: the rule keeps firing, so what it classifies tomorrow joins a share consented to today. That is the point — "share my financial knowledge" should stay true — but no preview can show a blast radius that grows after the fact, so the screen says it in words.

Settled · 26 Aug

Four answers, and what they opened

All four calls came back. Two were confirmed, one was overturned, and one grew into a bigger feature than it started as.

01

Opens on the pile · confirmed

And with a sharper goal than I had: the point is not to browse a pile, it is to empty it. So the count wants a direction — "3,107, down 312 today" is a job in progress; a bare number is just a fact.

02

Plainer words · overturned, and it changed the model

Not a rename. DIKW becomes the default bucket set rather than the vocabulary, and a person names their own — financial knowledge, engineering information, trash.

Each bucket keeps a DIKW rung underneath, because the sharing floor is literally a floor and Data is what unclassified falls to; a flat set of labels has neither. The bucket is the person's word, the rung is the machinery's.

03

“Classify” · confirmed against my recommendation

It is what the system does, and precision won over familiarity. Copy can change later if it proves confusing in use.

04

Always preview · confirmed, and then some

Preview and apply are one flow. Beyond that, a rule now has to show its yield and act on it — delete the rule, delete the data, or share everything it classified. That is screen 5, and it is the largest thing to come out of this round.

→

Three things these answers opened

Trash cannot be stated yet. "Everything except trash" is an exclusion, and the rule language has no not. Until negation lands it is a bucket at the Data rung plus a suppression flag the read path honours.

A share can now be a rule, not a list. That is a real change to the sharing design, where the share unit was a set of items. It needs to be revocable as one thing.

Creating a bucket has blast radius. A bucket placed at the wrong rung silently changes what is shareable, which argues it deserves the same preview treatment as editing a rule.
