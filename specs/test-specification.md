# Test Specification

> Generated by /test-spec from blueprint artifacts.
> Last updated: 2026-04-22

## Overview

This test specification covers the remaining ferrosa-memory blueprint scope after Sprints 1-6: shared HTTP deployment hardening (Sprint 7), the expert-system knowledge plane plus integrated operator workbench (Sprint 8), the role-aware boundary correction for Sprint 9, and the planned server-owned `ingest_entities` batch contract for Sprint 10. The system under test is the existing Rust workspace centered on `ferrosa-memory-core` and `ferrosa-memory-mcp`, with a converged rule loader and landed governance backend surfaces in place, plus explicit architectural work to eliminate direct graph-table writes, complete passthrough operator query surfaces, and add a fail-loud bulk-ingest surface that keeps clients out of CQL schema ownership.

The current baseline already includes HTTP transport, split liveness/readiness probes, viz routes, anomaly subscriptions, stored Datalog rules, and derived-fact query support. Backend convergence and governance surfaces are now implemented (`manage_rules`, `query_derived`, `recursive_explore`, `promotion` share the effective loader; `manage_claims`, `manage_approvals`, `manage_aliases`, `explain_derived`, and `get_effective_rule_set` are implemented). Remaining highest-risk work is shared-HTTP production hardening, operator query/workbench rollout, and a new bulk-ingest surface that must never reproduce silent row drops or client-owned schema drift.

Coverage highlights:

- Layer 1 Unit: 13 scenarios
- Layer 2 Contract: 6 scenarios
- Layer 3 Integration: 11 scenarios
- Layer 4 System: 8 scenarios
- Layer 5 Property: 4 scenarios
- Layer 6 Performance: 4 scenarios
- Layer 7 Load & Duration: 3 scenarios

Known implementation baseline informing this spec:

- Shared HTTP startup validation exists, but end-to-end safety and secret-wiring hardening still need full coverage.
- `/viz`, `/viz/ws`, `/subscribe/anomalies`, and `/viz/api/derived_facts` exist today; the integrated workbench rooted at `/` and separate CQL/Datalog explorer surfaces are still in progress.
- Governance/knowledge-plane backend paths are now implemented and aligned through the shared effective loader, with management and explanation MCP tools shipped.
- The next highest-risk work is the role-aware boundary cutover: graph writes must stop bypassing public Cypher, workbench query paths must become true public-API passthroughs, and serving startup/readiness must succeed without graph-table `MODIFY`.
- The planned `ingest_entities` surface adds new high-risk contracts: row-level failure honesty, conflict semantics, server-owned schema/version drift handling, optional server-side embeddings, strict edge validation, and dry-run safety.
